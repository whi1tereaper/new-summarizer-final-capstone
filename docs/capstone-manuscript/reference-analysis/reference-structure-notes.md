## Numbering, captions, tables, and diagrams

Figures use a single sequence across chapters, beginning with the research paradigm and ending with deployment evidence. Captions use `Figure N. Description` and generally appear beneath the visual. The figure list has 30 entries: research paradigm; lifecycle model; locale photograph; location map; Gantt chart; use cases; context DFD; Level 1 DFD; six Level 2 DFDs; unnormalized and first normal forms; ERD; development tools; application pages; and deployment. Diagram explanations refer to the figure and describe actors, transformations, data stores, and outputs. The new project's figure count may differ because its actual workflows and pages differ.

Tables have one continuous 1–21 sequence. Captions use `Table N. Description` and appear above the table. Table 1 is the respondent distribution, tables 2–3 define response-scale interpretations, tables 4–8 are data dictionaries, table 9 is estimated cost, tables 10–17 cover technical evaluation and its summary, and tables 18–21 cover end-user evaluation and its summary. Quantitative tables typically have characteristic/category, weighted mean, and verbal interpretation columns. Each table is introduced or interpreted in nearby prose. Table 2's caption is on printed page 33 but its body is on page 34; avoid that split in the new editable manuscript.

The reference contains author–year citations but inconsistent bibliographic completeness and ordering. The bibliography is a presentation reference only, not an approved source set for this project. URLs must not be assumed to validate the stated title, author, or year without checking.

## Errors and inconsistencies not to carry forward

1. **Conflicting rating scales:** PDF page 49 describes a five-point agreement questionnaire, while pages 53 and the resulting tables use ranges ending at four. Instrument, scale, analysis formulas, and result interpretation must agree before any new evaluation is conducted.
2. **Inconsistent verbal labels:** summary prose on PDF page 124 labels results differently from the evaluation summary on page 122 and the abstract. The selected approved interpretation must be used consistently.
3. **Methodology template contamination:** PDF pages 41–42 describe business sales/inventory planning even though the reference is a different type of project. This is an editorial defect, not a model for the new methodology section.
4. **Unsubstantiated methodology details:** lifecycle stage names vary between conceptual framework, questions, methods, and Chapter III. Pair programming, sprints, continuous integration, stakeholder consultation, and similar historical claims cannot be inferred merely because an application exists.
5. **Inconsistent evaluator criteria:** PDF page 49 names a set of technical criteria different from pages 34 and 51. The new study needs one approved criteria set and explicit treatment of any omitted characteristics.
6. **Temporal inconsistency:** the cover is dated 2025, while the literature and references contain 2026 entries. Dates must be verified for the new project; do not copy those references or infer a development period from them.
7. **Editorial instruction left in prose:** PDF page 30 addresses the writer about adding literature. Manuscript prose should describe the study, without leftover drafting instructions.
8. **Manual heading duplication:** the password-recovery and registration entries both use section C. Use one alphabetic sequence in the new manual.
9. **Inconsistent password-recovery wording:** one manual passage suggests sending a password, while the following passage describes a reset link. Document the audited application's actual behavior precisely.
10. **Unsupported improvement language:** time reduction and strong effectiveness/security claims appear without comparative measurements in the reviewed discussion. The new audit must distinguish intended benefits from measured outcomes.
11. **Scope/results tension:** the stated scope is limited to basic functional testing, yet other sections use broader quality and research claims. Scope must match the actual evidence gathered.
12. **Unverified bibliography:** some entries have incomplete author data, missing publication details, merged entries, irregular ordering, and a DOI/title/year combination requiring verification. Do not import them into the new bibliography.
13. **Recommendations overlap stated features:** some recommended functionality overlaps capability claims elsewhere. Recommendations must identify the exact missing or deficient behavior found in the current project.
14. **Maintenance content exceeds earlier descriptions:** additional capabilities appear in the maintenance manual without consistent introduction elsewhere. Cross-check every manual feature against the inventory and implementation evidence.
15. **Typography/layout inconsistencies:** split table captions, overspaced justified lines, narrow text measure, inconsistent heading capitalization, awkward page breaks, and a switch in maintenance-manual font should not be replicated blindly.
