# Security and reliability audit

Audit date: 17 October 2026, Asia/Manila. Scope: source review, direct read-only schema metadata and isolated synthetic fixtures. No production exploitation, account changes, document reads, migration execution, email, cleanup or live HTTP requests were performed. Ratings below express engineering priority; they are not a formal penetration-test score or a certification.

## Controls present in the source

The audit found PHP password hashing, randomized/reset OTP generation, rate-limit services, session regeneration, prepared SQL, CSRF checks on main/account/admin mutations, guarded history/job access and administrator OTP. These controls reduce specific risks but do not compensate for the separate document API defect. Remembered login uses hashed rotating validators and refuses automatic administrator login.

URL resolution restricts schemes and addresses, revalidates redirects and DNS, pins approved addresses, verifies TLS, disables proxy use and bounds response size/time. File acceptance validates actual uploads, MIME/magic and DOCX package structure. Python invocation uses structured arguments/JSON, timeout handling, private temporary paths and a localhost authenticated supervisor. No control was tested by sending requests to external or internal hosts during this audit.

The main error contract categorizes input/upload/network/extraction/worker failures and supplies user-facing messages, retry data and bounded recovery. Jobs use identity-scoped idempotency, atomic claim and worker-ownership checks. Evaluation runs preserve snapshots and fingerprints, distinguish missing metrics, bind review assignments to users, require reasons for corrections and retain audit entries. These are source-supported safeguards, not measured service-level guarantees.

Apache `.htaccess` defines CSP, frame denial, MIME sniffing protection, referrer/permissions policies and HTTPS-conditional HSTS. CSP still allows inline script/style. Effective headers depend on Apache module/override settings and are not applied by the PHP development server. Cookie Secure detection differs between session and remember-me implementations; reverse-proxy deployment should explicitly validate trusted forwarding behavior. Rate limiter IP forwarding has an allowlist separate from that cookie logic.

## Isolated verification record

The audit harness `evidence/backend_isolated_checks.php` loads the real document controller/service and injects in-memory SQLite. A synthetic document belongs to user 101. User 202 receives its text with 200; an empty session also receives it with 200. These two expected-denial assertions fail and substantiate SEC-01. They do not show that any actual user's document was read. The third assertion constructs a named synthetic audio fixture inside the evidence directory, invokes the actual range service, records the incorrect suffix response and removes that fixture.

| Test ID | Expected | Observed | Interpretation |
|---|---|---|---|
| BACKEND-FIXTURE-01 | Deny another user's document | 200 and synthetic source content | FAIL: ownership boundary missing |
| BACKEND-FIXTURE-02 | Deny document without owner context | 200 and synthetic source content | FAIL: ownership boundary missing |
| BACKEND-FIXTURE-03 | 206 with 100 bytes for `bytes=-100` on 1,000-byte file | 200 with 1,000 bytes | FAIL: suffix-range handling |

Raw machine-readable observations are in `evidence/backend-isolated-checks.json`. These three failures are deliberate audit checks, not a claim that the application passed security testing. Database metadata inspection succeeded independently. Syntax and Python/browser fixture results are recorded by their corresponding audit reports and must not be added to this three-case count twice.

## Verification still required before deployment

Use a disposable database and synthetic accounts to verify full registration/login/admin OTP/reset, token revocation, terms, guest conversion/expiry, owner/share access, concurrent jobs and cancellation, multipart upload/extraction, TTS/translation, feedback, all administrator mutations, and evaluation worker/ratings/export. Prove clean install and upgrade separately, including `password_resets`. Exercise hostile input and cache/header behavior against the intended hosting configuration. Measure performance with representative approved content and stated hardware; do not infer capacity from configured limits. Perform a documented restore drill before claiming recoverability.

No remediation was applied in this documentation-only audit. Findings are evidence for future authorized implementation work and honest manuscript limitations, not invented participant feedback or research effectiveness results.
