# Known Issues and Verification Gaps

Audit date: 17 October 2026 (Asia/Manila). No application remediation was applied. All entries remain open at this audit snapshot. Priorities express engineering judgment, not a formal vulnerability score or a count of affected users. The register contains **30 findings/limitations: 6 High, 20 Medium, 4 Low**. A capability or documentation gap is not automatically an exploitable defect.

Evidence classes: **ISOLATED** means the named behavior was executed against synthetic data/source copies; **METADATA** means actual database definitions were observed without application rows; **SOURCE** means code/configuration was inspected; **UI** means source-template/DOM behavior was inspected with bootstrap bypassed. Live exploitation, real account access and production mutation were not attempted. Recommendations and acceptance checks below are proposed work, not completed fixes/tests.

## Unresolved questions that are not confirmed defects

The blank-first-page PDF probe failed readability validation before physical-page reference alignment could be assessed. Source inspection raises an alignment concern, but the audit did not demonstrate an incorrect displayed citation number. Preserve this as an investigation target and test with a sufficiently readable multipage fixture before promoting it to a confirmed defect.

Translation provider acceptance, real speech quality, full scanned-PDF OCR coverage, optional embedding/LanguageTool/spaCy/model provisioning, effective Apache/proxy headers, multiuser job concurrency, real account/OTP state, backup automation and restoration remain unverified. Their absence from executed evidence is not proof that they all fail. These gaps require controlled integration/environment tests, not invented outcomes.

The direct Nutshell smoke record's PASS means the function returned a truthy object. Its payload explicitly reports insufficient_content and contains no generated text. Treating this as successful generation would be an evidence interpretation error. Similarly, synthetic zero dashboards, test run time, repository pilot reports and product feedback must not be converted into human survey results, measured deployment performance or study effectiveness claims.

## Proposed remediation order

1. Restore document ownership and consistent mutation/error guards; resolve password-reset revocation and every administrator status path.
2. Reconcile the reset schema and prove a disposable fresh installation/upgrade before relying on account recovery.
3. Fix legacy prose cleaning and the optional-v2 regression, with representative extraction/source tests and exact preserved meaning checks.
4. Correct audio range/cache handling, guest lifecycle, upload cleanup references and analytics data/denominators.
5. Resolve inaccessible evaluation administration and history navigation, then address keyboard/label/landmark issues and misleading copy.
6. Complete authenticated source-to-result, external-service and operational tests in an isolated deployment; conduct approved human evaluation separately.
